# x402 pay-per-call mode

Optional alternative authorization for the read-only Zerion source. Instead of
an API key, a dedicated payment wallet pays about $0.01 USDC on Base per API
request through the [x402](https://x402.org) protocol.

## What x402 is

x402 is an open pay-per-request HTTP protocol (Coinbase origin, now a Linux
Foundation project). The flow:

1. Client GETs a Zerion endpoint with no API key.
2. Zerion answers HTTP 402 with payment requirements in a header.
3. The x402 SDK signs a USDC payment authorization on Base and retries.
4. Zerion settles the payment and returns the data.

Zerion documents this as the same API, same endpoints, same responses; only
the authorization changes. No signup, no key rotation, no rate-limit quota.

## Setup

```bash
pip install -e '.[x402]'                       # or '.[x402,mcp]'
export ZERION_X402_PRIVATE_KEY=$(cat ~/secrets/x402-payment-key)
export ZERION_WALLET_ADDRESS=0xObservedWallet
zpm-mcp
```

| Variable | Required | Meaning |
|:--|:--|:--|
| `ZERION_X402_PRIVATE_KEY` | yes | Private key of a dedicated payment wallet on Base |
| `ZERION_WALLET_ADDRESS` | yes | The wallet Scout observes |
| `ZERION_X402_MAX_USD_PER_CALL` | no | Per-call spend cap, default `$0.05` |
| `ZERION_CHAIN` | no | Snapshot label, default `multi-chain` |

Setting `ZERION_API_KEY` and `ZERION_X402_PRIVATE_KEY` together is a startup
error. Pick one mode.

The payment wallet needs a little USDC on Base and enough ETH on Base for gas.
Keep it small and dedicated: its private key lives in the server environment.
A wallet with $5 USDC funds roughly 500 calls.

## Boundaries

- Scout stays read-only. The only onchain action is the per-call data fee
  from the payment wallet. The observed wallet never signs anything.
- The spend cap is enforced client-side by the x402 SDK before any payment
  payload is signed. The default `$0.05` leaves headroom over the ~$0.01
  list price while bounding worst-case loss per request.
- Cost per snapshot is bounded: `max_pages` (default 20) caps the paginated
  transaction walk, so one `get_portfolio_snapshot` costs at most about 21
  calls (~$0.21 at list price).
- The private key never appears in logs, errors, reprs, or tool results.
- No fixture fallback: if a paid call fails, the host returns a typed error.

## Errors

HTTP 402 after payment attempt maps to observe-error kind `payment`
(`retryable: false`). Retrying blindly would spend money again for the same
failure. Common causes:

- Payment wallet has no USDC on Base, or no ETH for gas.
- The spend cap is below the endpoint's price: raise
  `ZERION_X402_MAX_USD_PER_CALL`.
- Facilitator settlement hiccup: a single manual retry is safe; automated
  retry loops are not.

Other error kinds (`transport`, `server`, `rate_limit`) behave as in API-key
mode.
